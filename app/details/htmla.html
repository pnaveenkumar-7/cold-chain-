Cold Chain Traceability Node (SIH26232)

Complete Technical Specification, Engineering Rationales & Updated Bill of Materials

1. System Architecture & Problem Statement Alignment

This node provides continuous environmental and physical tamper tracking for temperature-sensitive cargo (pharmaceuticals, dairy, and agricultural produce)[cite: 1, 2]. Designed for Smart India Hackathon problem statement SIH26232, the system maintains integrity across cellular dead zones via a local append-only cryptographic hash chain on non-volatile flash storage[cite: 1, 2].

When cellular connectivity returns, unsynced readings upload via MQTT over TLS to an ingestion backend[cite: 1, 2]. The backend validates chain continuity, computes a Merkle root, and anchors the proof onto the Polygon Amoy testnet[cite: 1, 2].

3. Hardware Rationales: Essential Additions vs. Exclusions

Engineering Rationales for Added Components

  • 1000 µF Low-ESR Buffer Capacitor: The SIM800L draws current spikes up to 2.0A during cellular handshakes. Breadboard rails and thin wires have resistance that causes instant voltage drop. Without this capacitor placed directly across the modem's power pins, the supply rail drops below 3.4V, causing brownout reset loops on both the SIM800L and the ESP32.
  • TP4056 with Protection (DW01A + FS8205A): Standard 2-terminal chargers do not protect the battery during discharge. The protected version provides dedicated OUT+ and OUT- terminals that isolate the load if battery voltage falls below 2.5V, preventing permanent cell damage.
  • SPST Slide Switch: Provides a clean physical power disconnect between the battery and the MT3608 boost converter, avoiding the need to yank wires or battery contacts during bench flashing and debugging.
  • Discrete Passive Components: Replaced bulk commercial component kits (costing ₹465) with targeted packs of discrete LEDs and resistors, reducing costs by over ₹400 while retaining necessary circuit diagnostics.

Items Excluded from Scope & Evaluated Alternatives

  • LoRa RA-02 (SX1278): LoRa requires dedicated gateway base stations within 2–10 km line of sight. Long-haul refrigerated freight travels along major highways where private gateways do not exist. Cellular 2G GPRS already provides wide national coverage, making LoRa an unnecessary redundancy.
  • USB Type-A to Micro-USB Cable: Excluded from the billable BOM because it is a generic lab bench utility item that artificially inflates prototype hardware costs.
  • ATECC608A Cryptographic Co-Processor: Difficult to procure locally and requires complex I2C key provisioning. The ESP32's internal hardware-accelerated SHA-256 engine combined with mbedtls meets all cryptographic integrity and hash-chaining requirements without extra chips[cite: 1, 2].
  • 6V Solar Energy Harvesting Panel: Cold chain cargo travels inside lightless, heavily insulated metal reefer boxes[cite: 1, 2]. Solar generation is physically impossible inside the hold, and piercing the container wall for external wiring compromises thermal insulation.
  • IP65/67 Enclosure (During Bench Stage): Sealed enclosures make probe debugging and rewiring difficult during development[cite: 1, 2]. Open breadboards or clear acrylic housings are preferred for hackathon jury evaluation.
  • 5V Active Buzzer Module: Acoustic alerts placed inside sound-insulated transport trucks cannot be heard by the driver. Tamper violations are instead recorded immutably on-chain and alerted via the web dashboard[cite: 1, 2].
  • Secondary ESP32-CAM Architecture: If visual tamper evidence is desired, the ESP32-CAM must not run continuous video loops. It should be wired as an event-driven slave device in deep sleep, waking only when the physical tamper switch triggers an external interrupt, saving a single snapshot to its local SD card before powering down.

5. Smart Contract Implementation (Polygon Amoy Testnet)

// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

/**
 * @title ColdChainTracker
 * @notice Verifies tamper-evident IoT cold chain telemetry batches on Polygon Amoy.
 */
contract ColdChainTracker {
    struct BatchProof {
        bytes32 merkleRoot;
        string storageURI;       // IPFS CID or backend record pointer
        uint256 committedAt;
        bool tamperBreach;
        address reporter;
    }

    mapping(string => BatchProof[]) private shipmentBatches;

    event BatchCommitted(
        string indexed shipmentId,
        bytes32 indexed merkleRoot,
        bool tamperBreach,
        uint256 timestamp
    );

    function commitBatch(
        string calldata shipmentId,
        bytes32 merkleRoot,
        string calldata storageURI,
        bool tamperBreach
    ) external {
        shipmentBatches[shipmentId].push(BatchProof({
            merkleRoot: merkleRoot,
            storageURI: storageURI,
            committedAt: block.timestamp,
            tamperBreach: tamperBreach,
            reporter: msg.sender
        }));

        emit BatchCommitted(shipmentId, merkleRoot, tamperBreach, block.timestamp);
    }

    function getBatchCount(string calldata shipmentId) external view returns (uint256) {
        return shipmentBatches[shipmentId].length;
    }

    function getBatchProof(string calldata shipmentId, uint256 index) 
        external 
        view 
        returns (
            bytes32 merkleRoot,
            string memory storageURI,
            uint256 committedAt,
            bool tamperBreach,
            address reporter
        ) 
    {
        require(index < shipmentBatches[shipmentId].length, "Index out of range");
        BatchProof memory b = shipmentBatches[shipmentId][index];
        return (b.merkleRoot, b.storageURI, b.committedAt, b.tamperBreach, b.reporter);
    }
}
